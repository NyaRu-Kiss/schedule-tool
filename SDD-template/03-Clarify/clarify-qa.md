# Clarify — 需求澄清 Q&A

> 本文档记录对 PRD 和设计稿的挑战性问题及其澄清结果。
> 每条问题对应一个潜在的歧义、边界缺失或假设冲突，澄清后即时回写。

---

## Q1：同一 VIN 重复提交检测任务的处理逻辑

**问题**：PRD 3.1 说"同一 VIN 允许重复提交，不作废历史任务"，但列表页没有说明如何区分同一辆车的多条任务。评估师会不会误操作重复创建？

**澄清**：列表页按创建时间降序展示，同一 VIN 的多条任务自然排列在一起。前端列表在 VIN 列增加"重复"角标提示（当同一经销商下同一 VIN 存在多条进行中任务时显示）。

---

## Q2：LTO 下发任务的认证方式

**问题**：接口标注 `[AllowAnonymous]`，但实际是否需要 IP 白名单或 Token 认证？

**澄清**：确认使用 API Key 认证（Header：`X-Api-Key: {LTO_API_KEY}`），Key 存储在后端配置文件中。LTO 侧提供固定 API Key，不做 IP 白名单（部署环境 IP 不固定）。

---

## Q3：企微发送失败后短信降级的时机

**问题**：T09 业务逻辑中，企微查群失败和顾问不在群都降级短信，但"企微调用超时"是否也降级？超时阈值是多少？

**澄清**：企微调用超时统一降级短信，超时阈值设 3 秒（HttpClient Timeout=3s）。超时、网络异常、接口返回非 200 均视为失败触发降级。

---

## Q4：厂端 PC 查看报告是否需要手机验证

**问题**：客户查看报告需要短信验证码，但厂端管理员从 PC 列表点击"查看报告"时，是否也要走验证流程？

**澄清**：厂端 PC 查看报告**免验证**，通过后端专用接口 `GetReportDataAdmin`（需登录态 Token），直接返回报告数据，不走 SMS 验证流程。此接口与客户端 `GetReportData` 分开，以区分权限层级。

---

## Q5：ReportStatus 状态流转中"已发送"与"待查看"的前端展示

**问题**：ReportStatus=1（已生成）和 ReportStatus=2（已发送）在前端列表都显示为"待查看"，但两者对评估师的操作意义不同。是否需要区分展示？

**澄清**：按 PRD 当前设计合并展示为"待查看"，不区分。

---

## Q6：漆面厚度标准值的来源与可配置性

**问题**：17 项漆面厚度标准值在后端硬编码，未来是否需要按车型配置？

**澄清**：当前版本硬编码，后续如需配置化走新需求。
