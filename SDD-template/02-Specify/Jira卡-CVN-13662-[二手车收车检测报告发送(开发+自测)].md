h3. {color:#de350b}PO需求{color}

评估师将检测报告链接发送给客户后，客户需要通过手机号验证才能查看报告内容。这一验证机制确保报告只能被指定的客户查看，防止链接被无关人员访问。客户打开链接后，系统弹出验证页面，要求输入手机号和短信验证码；客户输入的手机号必须与检测任务中录入的客户手机号一致，否则无法获取验证码。

验证通过后，系统根据客户设备的屏幕宽度自动判断展示手机端布局还是 PC 端布局，两种布局使用同一个报告链接，无需客户手动切换。手机端布局基于 Vant 组件，竖向展示，仅显示有问题的检测项；PC 端布局采用宽屏分栏设计，可展示更完整的检测信息。

本卡为后端短信验证接口（SendSmsCode、VerifyCode）开发 + 前端客户验证页面 + 手机端/PC 端报告页面开发 + 自测。

h3. {color:#00875a}用户故事{color}

* 用户/系统: 企业微信二手车 H5（nbms-usedcar-h5）+ project-v-ucm 后端 API + 短信服务

* 行为: 基于 03-经销商收车检测模块 PRD 及技术方案，在 project-v-ucm 实现 SendSmsCode 和 VerifyCode 两个匿名接口，在 nbms-usedcar-h5 实现客户端验证页面、手机端报告页面和 PC 端报告页面，完成客户从验证到查看报告的完整链路。

* 价值: 通过手机号验证机制保障报告的安全性，同时通过双端自适应布局提升客户查看报告的体验。

h3. {color:#ffab00}验收标准{color}

| *前置假设条件* | *业务行为举例* | *期望结果* |
| 客户首次打开报告链接 | 客户在手机浏览器打开报告链接 | 展示验证页面，要求输入手机号和验证码 |
| 客户输入与任务不符的手机号 | 客户输入错误手机号后点击"获取验证码" | 系统提示"手机号不正确"，不发送短信（不暴露具体原因） |
| 客户输入正确手机号 | 客户点击"获取验证码" | 系统发送 6 位短信验证码，验证码 5 分钟内有效，按钮进入 60 秒倒计时 |
| 客户输入错误验证码 | 客户输入错误验证码后点击"确认" | 系统提示"验证码错误"，不跳转 |
| 验证码已过期 | 客户 5 分钟后输入验证码 | 系统提示"验证码已过期，请重新获取" |
| 客户输入正确验证码 | 客户点击"确认" | 验证通过，根据屏幕宽度自动跳转手机端或 PC 端报告页 |
| 客户在手机端查看报告 | 客户在屏幕宽度 < 768px 的设备打开 | 展示手机端竖向布局，仅显示有问题的检测项和对应照片 |
| 客户在 PC 端查看报告 | 客户在屏幕宽度 ≥ 768px 的设备打开 | 展示 PC 端宽屏布局，分栏展示车辆信息和检测结果 |
| 客户已验证过，刷新页面 | 客户刷新报告页 | 无需重新验证，直接展示报告（sessionStorage 中有验证标记） |
| 客户关闭标签页后重新打开链接 | 客户重新打开报告链接 | 需要重新验证（sessionStorage 已清除） |
