# Clarify — 需求澄清记录

## 已确认事项

### Q1：MCP 的数量和职责是什么？

**结论**：系统只提供一个日程 MCP。它作为 WorkBuddy 与日程 Agent 之间的连接器，暴露创建日程、查询待提醒、确认提醒三个工具，并将请求转发给 Agent；MCP 不直接调用后端或访问 MySQL，不承载最终业务校验。

### Q2：Agent 是否放入 MCP？

**结论**：Agent 与 MCP 分开。MCP 负责 WorkBuddy 侧的协议适配和请求转发，Agent 负责意图识别、结构化参数处理和后端调用。

### Q3：“什么时候有空”具体指什么？

**结论**：它不是独立的空闲时间查询能力。用户创建日程但未指定开始时间时，系统根据已有日程和约束自动寻找空闲时间段并插入日程。

### Q4：是否需要工作流编排引擎？

**结论**：当前流程固定，不引入工作流编排引擎。WorkBuddy 通过固定调用路径使用 Agent、MCP 和后端。

## 实现前需要配置确认的参数

以下内容不改变当前架构，但需要在后端落地前配置：

1. 默认工作时间和可自动排期的日期范围。
2. 日程允许的最大时长和最小时间粒度。
3. 提醒提前时间的允许范围。
4. WorkBuddy 定时任务的轮询间隔。
5. Agent 到后端的服务认证方式。
6. 用户时区的来源和默认值。
